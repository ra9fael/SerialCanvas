**其中一项报告需要更正**，另有一项不是缺陷而是值得重新审视的设计决策。

## 1. 工具栏控件有四种高度（真实）

在 1600x1000 下用**泛化选择器**测量（抓所有可见控件，不只是带标签的芯片）：

| 高度 | 数量 | 是��� | 来源 |
| --- | --- | --- | --- |
| 39px | 1 | 导出日志 | `.secondary-btn` 的 `padding: 10px 16px`，无高度 |
| 34px | 6 | 字号, 回滚行数, 日志字符, 换行, 字体, 主题 | `.term-field` 是 `min-height: 30px`，但内含 32px 触发器加边框撑到 34 |
| 32px | 6 | 六个下拉触发器 | `--control-h` |
| 30px | 4 | 视图切换(2), Echo, 清空缓存 | `min-height: 30px` |

**四种高度、三种机制**，而你点名的两个按钮和它们旁边的下拉框不在同一行。

### 修法

`--control-h-sm`（28px）已经为密集芯片定义了，但工具栏应该用**一个**值：32px，
与 `--control-h` 一致。

- 工具栏内的 `.secondary-btn` / `.mode-tab`：把 padding 算术换成
  `height: var(--control-h)` + `padding: 0 10px`。全局 `.secondary-btn`
  保留原 padding —— 这是**工具栏作用域**的覆盖，因为同一个类在别处
  （图表条、发送面板）用 39px 是对的。
- `.term-field`：34px 来自"把 32px 触发器包进一个自带 min-height 和 padding 的盒子"。
  两个选择：
  - 给 `.term-field` `height: var(--control-h)` 让触发器填满它，
    芯片变成控件的**外框**而不是**容器** —— 更干净，也与 `2375f30` 之后
    `.toggle-row` 的做法一致；
  - 或对无勾选框的裸下拉去掉 `.term-field` 这层，省 2px 边框和一层嵌套。

  我会对**带标签的**用第一种、对**裸下拉**用第二种，
  这样一行里只在"有标签的字段"与"匿名控件"这个区分有意义的场合才混用两种外观。

一条实测说明：工具栏在 1280–1440px 下已经堆到 3–4 行
（`audit/measure-toolbar.mjs`）。统一高度能让行高减 7px，但**不改变行数**；
本轮尝试压缩换行反而在 1280px 引入了溢出控件，已回退。换行问题单列在第 5 节。

## 2. 协议设置面板现在是冗余的

同意，而且这是刚做完那件事的连带结果，不是独立的观察。

`8a0effd` 之前左栏只有连接面板，解析设置要通过图形解析开关够到。
`8a0effd` 把解析面板变成左栏第二行的默认住户，于是左栏现在显示：

```
设备连接管理      连接参数、波特率、流控、信号
协议设置          解析模式、规则框、二进制结构表
实时解析结果      实时卡片、模拟器
```

这个读法说得通 —— 但你看到的是**三分之一屏幕专门给解析配置**，
而这个工具的主职是串口控制台。实际上解析面板在配置协议时需要，之后就多余了。

### 三个选项

| 选项 | 效果 | 代价 |
| --- | --- | --- |
| **折叠成标题条** —— 标题 + 开关，主体默认收起 | 左栏回到「连接 + 结果」，解析设置一键可达 | 每个会话多一个状态 |
| **空闲时自动折叠** —— N 秒无 RX 就收起，有数据或点击时展开 | 同上，用户无需操作 | "空闲"是主观判断；慢速设备会一直保持折叠 |
| **移到弹窗** | 左栏纯连接 + 结果 | 规则框是多行编辑器带语法高亮和内联帮助，弹窗太挤且失去与结果的并排 |

我推荐第一种，状态持久化在 `layout.parserPanelOpen`，**默认折叠**。
持久化很关键：每周配置一次协议的人不该每次会话都重新打开。

**诚实的反方论点**：模拟器在结果卡里，折叠解析面板会把新手应该一起试的两个东西
藏起来。所以 `模拟数据` 要能从折叠条上够到。

## 3. 模拟需要可配置，且 A5 帧无法解析

两个独立问题。第二个是我引入的真缺陷。

### 3a. A5 帧无法解析 —— 实测确认

模拟开启、脚本 `binary-frame`、二进制解析模式：

```
rxRows: 2          数据确实在到达
parseCards: 2      ["int0  -", "checksum  -"]
```

两张卡的值都是空 —— 帧收到了但没解出来。

**根因：脚本与默认结构表不匹配。**

| | 脚本产出 | 默认结构表期望 |
| --- | --- | --- |
| header | `A5` | `A5` ✓ |
| data | **两个字节**（`temp*10`, `hum`） | **一个 `int8` 行** |
| checksum | `SUM8` | `SUM8` ✓ |
| footer | `5A` | `5A` ✓ |

脚本自己的注释声称"matches the default seeded schema"，**这个说法是假的**：
`state.parser.binarySchema` 默认是 `[]`（`app.core.js:486`）。
`ensureBinarySchemaRow()` 会播种 `header / data / checksum / footer` ——
**一个** data 行 —— 但只在二进制面板被渲染时，而那在图形解析开关后面。
所以默认视图下根本没有结构表。

**这是我第二次写"声称两者对应"的注释而没验证**（第一次是 B1 方案里的
`#term-newline`）。**声称两件事对应的注释，本身就是需要测试的断言。**

### 3a 的修法

两件事都值得做：

1. **让脚本匹配单行结构表** —— 用 `uint16le` 一个字段打包两个字节，
   或只发一个数据字节。更省，且不动默认结构表。
2. **更好：让二进制脚本声明它需要的结构表**，选中脚本时自动填入。
   模拟器的全部意义就是让解析器可演示，所以它不该要求用户手工建结构表
   才能看到一个解码值。选中 `binary-frame` 就把匹配的行写进结构表。

我推荐 2，并保留 1 作为它写入的结构（一个名为 `reading` 的 `uint16le` 行；
如果想分开看两个值就再加一行 —— 类型表已有 `uint8`/`uint16le`/`float16le`/
`float32le`）。

验证标准：**二进制卡片必须显示变化的数字，而不是 `-`**。
这条断言本来就能抓到这个问题。

### 3b. 可配置项

目前只有开关和脚本选择（`SIMULATION_SCRIPT_IDS`，`app.core.js:96`）。
值得加的，按价值排序：

| 项 | 为什么 | 成本 |
| --- | --- | --- |
| **发送间隔** | 700ms 是任意的。60ms 的快速协议演示和 5s 的慢速传感器都合理，今天都够不到 | 一个 `<select>`，持久化 |
| **每次帧数** | 设备很少严格每次一帧。1/4/16 能演示解析器如何处理积压 | 一个 `<select>`，成倍调用 `queueRxBytes` |
| **载荷模板**（`{temp}`, `{hum}`, `{n}`, `{ts}`） | 这才是让模拟器对测试**真实**规则有用的地方：填入设备实际字段名，检查解析器能否处理 | 一个文本输入 + 安全的展开步骤 —— 结果必须走 `encodeText`，绝不能 `innerHTML` |
| **波形**（正弦、锯齿、随机游走、常量） | 正弦和常量看三帧就分不出；随机游走和阶跃能暴露解析器边界情况 | 一个 `<select>` |

我建议做**间隔 + 每次帧数 + 模板**，跳过波形 —— 模板里的 `{n}` 已经覆盖了
波形选择器能演示的大部分，而波形选择器是这个面板里最难被发现的控件。

模板展开是唯一有真实风险的地方：**它必须是编码字节上的纯字符串替换，
绝不能是 HTML**。模拟器产出的一切都走 `queueRxBytes()`，
所以能产出二进制帧的模板需要编码模式 —— 我会把模板限定为纯文本，
二进制脚本保持固定。

## 4. 按键条继续增加，包括 Enter

同意。34 个键，Enter 是最显眼的缺失。

### Enter 已被正确处理

`handleTermData` 对裸 `\r` 有特殊处理：

```js
if (data === '\r') {
  return getTermLineEnding() || '\r';   // 遵循用户选的换行符
}
```

所以 Enter 按钮必须发 `\r`，它会自动遵循「换行」下拉
（`none` / `\r` / `\n` / `\r\n`），而不是写死一个。
**按钮发的是回车符，不是"行结束符"，所以现有设置继续有效** —— 这点值得说明。

### 加什么

| 键 | 字节 | 为什么 |
| --- | --- | --- |
| **Enter** | `\r` | 缺失的主要按键 |
| **Shift-Tab** | `\x1b[Z` | 反向 Tab —— readline 上下文里越过补全菜单的唯一办法 |
| **Ctrl-Enter / Alt-Enter** | `\x1b\r` / `\x1b\x0d` | shell 把它们绑定成"接受但不执行"，多行命令暂存时有用 |
| **Ctrl-左/右** | `\x1b[1;5D` / `\x1b[1;5C` | 按词移动；Alt-B/F 已覆盖经典绑定，但方向键才是人们真正按的 |
| **Insert** | `\x1b[2~` | xterm 上报的最后一个导航键 |
| **F1–F4** | `\x1bOP`–`\x1bOS` | xterm 的应用模式形式；有些固件菜单绑这些 |

按键条从 34 增到 **44**。

### 分组

现有：导航 / 编辑 / 历史与补全 / 控制字节。新增：

| 组 | 键 |
| --- | --- |
| **提交**（新增，放最前） | Enter, Ctrl-Enter, Alt-Enter |
| 导航 | + Ctrl-左, Ctrl-右, Insert, Shift-Tab, F1–F4 |

Enter 单独一组放最前：**它是唯一提交一行的键**，埋进某个组里是错的。
它应该是按键条上最宽的按钮。

### 两条仍然成立的约束

1. **不用裸字母** —— 预设发送已在 `document` 上占用单键按下
2. **先 flush 粘贴缓冲** —— 这里相关：一大段文本之后的 Enter 不能超车
