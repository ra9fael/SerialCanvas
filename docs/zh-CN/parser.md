# 解析器参考

> 本文为[英文版](../parser.md)的中文镜像，逐节对应；如有出入以英文版为准。

解析器把输入的字节流转换为**具名数值通道**，供实时结果卡片与[图表](charts.md)使用。
两个引擎共用同一条流水线：

| 引擎 | 输入 | 配置位置 |
| --- | --- | --- |
| **文本解析** | 每帧一行已解码的文本。 | 配置文本 规则框。 |
| **十六进制解析** | 按字段表匹配的原始字节。 | 十六进制结构表。 |

在 **解析协议设置** 的标签页中切换两者。

- [文本规则](#文本规则)
- [十六进制帧](#十六进制帧)

- [限制与注意事项](#限制与注意事项)

## 文本规则

### 标记词汇

规则是一个普通字符串，在变动数据所在的位置插入**标记**。标记的形式严格为 `/` +
三个词之一 + 一位或多位数字：

| 标记 | 捕获内容 | |
| --- | --- | --- |
| `/intN` | `12`、`-3`、`+7` — 无小数点 | 整数 |
| `/floatN` | `3.14`、`.5`、`3.`、`42` | 数值 |
| `/nameN` | 形如 `温度`、`temp_1`、`chan-A` 的标签，或以空格分隔的若干词 | 文本 |

标记之间的所有内容都是**字面量**，必须与输入逐字符匹配（字面量会做 regex 转义，
因此 `=`、`,`、`[`、`(` 等可以放心原样书写）。规则中的空格和标点同样是模式的一部分 ——
`=` 与 `=`␣ 是两条不同的规则。

```
/name0=/float0,/name1=/int0;
```

匹配

```
temp=3.14,humid=61;
```

### 尾部数字绑定名称与数值

正是数字后缀把标签与它的数值配成一对：`/name1` 为 `/int1` 的值命名，`/name2` 对应
`/float2`。后缀可以重复使用（两个 `/int7` 标记是合法的），也不必连续。

- 若某个数值标记存在同后缀的 `/nameN`，且该名称捕获到了文本，则捕获到的文本**成为通道键**。
  这就是单条规则跟随动态标签的方式：

  ```
  Rule:   /name0=/int0
  Input:  sensorA=25      ->  channel sensorA = 25
  Input:  sensorB=30      ->  channel sensorB = 30
  ```

- 没有匹配的名称时，键由标记自身的类型与后缀构成：`int0`、`float1`。
- 没有同后缀数值搭档的 `/nameN` 会生成自己的文本卡片（不可绘制）。
- 未匹配到内容的可选名称会退回 `kind+index` 键，这会在你毫无察觉的情况下，把本应是一个
  通道的数据拆成两个。请让名称与数值保持成对。

### 规则的匹配方式

SerialWeb 按顺序尝试三种策略，在第一个能产出结果的策略处停止：

1. **锚定匹配。** 规则被编译为 `^<pattern>$`（Unicode），去掉首尾空白后的整行必须从头到尾
   完全符合。这种方式最精确，也最快。
2. **重复的 `name = value` 对。** 若规则恰好是一个 `/nameN` 后跟一个数值标记，则对整行做全局
   扫描，找出更多同形的 `label=value` 对，因此 `/name0=/int0` 也能解析
   `temp=42 humid=31 volt=3.3`。
3. **宽松的记号流。** 若规则至少含一个数值标记，则从行中切分出数字与词语，忽略字面量，按规则
   顺序从左到右依次消耗。绑定失败的值不保留任何内容；若完全没找到数值，该行不产生结果。

无法转换为数字的值会以文本形式保留，而不是被丢弃。不匹配的行不产生任何输出：没有缺测标记，
结果卡片继续按键显示上一次成功解析的值。

### JSON 回退

规则框**为空**时，解析器会尝试 JSON：先 `JSON.parse`，再做一次修复处理，应对无引号的键名与
单引号。对象按点号键展平（`a.b`），对象数组递归处理，数字数组下标渲染为 `arr[0]`。一旦你输入
任何规则，该回退即关闭。

### 分行处理

帧以 `0x0D`/`0x0A` 分隔；跨两次读取被拆开的 `CRLF` 仍属于同一帧。单条物理行超过
**2048 字节或 2048 字符**时会被拆成多个显示事件，每个事件独立解析 —— 协议帧应远小于该上限。
详见[用户指南 · 串口监视器的分行与缓存处理](user-guide.md)。

### 自动识别

规则框旁的按钮从流量中推断规则，而不必你自己编写：

1. 取当前会话最后 **12** 行（至少需要两行）。
2. 从最新行开始往前，逐对比较行，找出形态一致但取值不同的片段。
3. 若两行都是名称相同的 `name=value` 对，输出紧凑形式 `/name0=/<kind>0`；否则重建该行，
   把每个发生变化的片段替换为 `/nameN`、`/intN` 或 `/floatN`。

鼠标悬停或聚焦该按钮时，建议规则会以**幽灵文本**的形式预览在规则框内。按钮文案为
`自动识别：可用` 或 `自动识别：不可用`；点击不可用的建议不产生任何效果。按钮显示 可用
时确有真实建议 —— 该按钮从未真正被禁用。

连接之后，若存在建议且与你当前的规则不同，SerialWeb 会弹出可操作的 **发现解析可用** 提示，
提供两个选择：**应用添加并转到**（应用规则、为每个数值通道添加时域图、展开布局）或仅应用规则。
该提示每次连接只出现一次，且仅在实时、文本模式并且处于连接状态时出现。

## 十六进制帧

**十六进制解析**把帧描述为一张由若干行组成的表，自上而下地对字节流求值。新增一行 追加一行；
行可拖动排序；任何一次编辑之后 80 ms，表格会重新解析。

### 行类型

| 行 | 字段 | 行为 |
| --- | --- | --- |
| 帧头 | 十六进制字面量，默认 `A5` | 必须匹配。**留空表示整行跳过。** 第一个非空帧头用作字节流的同步标记。 |
| 数据 | 数据类型 + 标签 | 消耗该类型所占的宽度，输出一个通道。 |
| 校验和 | 固定 `SUM8` | 消耗 1 字节，与数据字节的累加和作比较。 |
| 间隔符 | 可选的十六进制字面量 | 留空消耗一个通配字节；填写则必须匹配。 |
| 帧尾 | 十六进制字面量，默认 `5A` | 必须匹配。**留空表示不检查帧尾**（宽松匹配）。 |

全新的表格以 `header / data / checksum / footer` 起始。

### 数据类型

| 类型 | 字节 | 类型 | 字节 |
| --- | --- | --- | --- |
| UInt8、Int8、Bool(8bit) | 1 | UInt32 / Int32 / Float32，LE 与 BE | 4 |
| UInt16 / Int16，LE 与 BE | 2 | UFloat16 / Float16，LE 与 BE | 2 |

`LE` 是小端序（低位字节在前），`BE` 是大端序。Float16 由软件解码，涵盖非规格化数、±0、±Inf
与 NaN；`UFloat16` 忽略符号位。没有 64 位整数，没有 Float64，也没有字符串或数组字段。

**Bool(8bit)** 是最值得注意的一种：它把父通道输出为 8 个字符的位串，**并且**额外输出八个数值
子项 `label.0 … label.7`（0/1），于是一个状态寄存器就成了八个可绘制的标志位。子项名称取自该行
的标签，因此标签要写得短些。

### 帧定界与重新同步

定位帧的方式是先搜索同步帧头，再从那里沿着结构表往下走：

- 字节足够且全部匹配 → 输出该帧，扫描从其之后继续。
- 字节暂时不足 → 保留尾部，解析等待下一段数据（一帧可以跨越任意多次读取）。
- 字面量不匹配 → 前进**一个字节**，重新搜索帧头。损坏或交错的数据被跳过，解析器在下一个
  帧头处重新同步。
- 若帧头始终不出现，只保留最后 `max(32, headerLength-1)` 个字节，因此空闲时的垃圾数据不会
  让缓冲区增长。

**只解析 RX。** 发送的字节会被归档并显示，但不经过结构表解析。

### 校验和

只实现了一种算法：**SUM8** —— 所有 `data` 行字节算术和的低字节（不计帧头、帧尾与间隔符字节，
`bool8` 按其原始字节参与）。

校验和行按数据处理，而不是一道闸门：收到的字节成为一个数值通道（默认名为 `checksum`），结果
卡片在匹配时变绿，不匹配时变红并显示 `expected!=received`。**校验和错误不会拒绝该帧** —— 若要
丢弃损坏的帧，请在下游你自己的分析中过滤。

### 通道

每个 `data` 行的标签都会成为 `parsed.<label>`；在你输入名称之前，自动命名依据该行在数据行中的
位置（`int0`、`uint1`、`float2`、`bool3`）。图表选择器与导出显示的就是这些标签，因此宜选用稳定、
不含点号的 ASCII 名称。

## 实时结果面板

**实时解析结果** 按键显示卡片，每个键一张，顺序为首次出现顺序：上方是 `key`，下方是数值，
配色与图表中该通道的曲线一致。

- 取值遵循**后写覆盖且粘滞**：字段停止到达后，卡片保留它的最后一个值；只有 清空缓存 或重置
  才会清空这个映射。
- 在首次匹配之前，面板显示占位符（`-`），文本模式下取自规则标记，十六进制模式下取自结构表
  标签，因此预期的布局立即可见。
- 只有当一行确实溢出时才会出现横向滚动条；此时 **展开 / 折叠** 可把卡片扩展为多行。
- 数值卡片供图表与分析导出使用。文本卡片（名称、位串）会作为通道被跟踪，但无法绘制。
- 原始辅助字段（`raw.*`）仅在内部用于统计，既不绘制也不导出。

## 限制与注意事项

| 限制项 | 数值 | 影响 |
| --- | --- | --- |
| 实时文本分析量 | 最近 320 个事件 | 实时解析忽略更早的缓存行。 |
| 时间线文本重解析 | 最近 12 000 个数据块 | 超长归档只有尾部会进入图表（分析*导出*不受此上限约束）。 |
| 时间线二进制重解析 | 最近 24 000 个数据块 | 同上。 |
| 帧长度 | 2048 字节 / 字符 | 更长的行会被拆成多帧。 |
| 实时缓冲区 | 8192 个解码字符 | 监视器不是归档 —— 请用 `REC` 录制。 |
| 匹配方式 | 仅子串 | 触发发送 没有精确匹配或 regex 选项。 |
| 校验和 | 仅 SUM8 | 无 CRC 变体。 |

实践提示：

- 用协议实际携带的字面文本尽量把规则锚定住。单独的 `/float0` 能匹配任意数字，宽松回退会从
  噪声里挑出一个值。
- 匹配之前会去掉行尾换行 —— 不要在规则里写 `\n`。
- 修改规则会从保留的缓冲区重新推导，因此结果会同时向过去和将来更新（受上述上限约束）。
- 终端视图完全绕过解析器（见[用户指南 · 终端视图](user-guide.md)）。
- 文本解析遵循 **字符编码** 设置；十六进制解析不遵循，因为它读取的是原始字节。

## 模拟数据源

模拟器在本地生成 RX，因此没有接设备也能验证解析、实时结果与图表。帧走的是串口读取所用的同一个 `queueRxBytes()` 入口，所以分行、解析、录制、绘图的全部行为与真实数据完全一致。串口已连接时它自动让位。

它是解析视图三部分中的第一部分（模拟 → 解析 → 图表），因为它是数据的来源。

### 脚本

| 脚本 | 发送内容 |
| --- | --- |
| 文本：传感器读数 | `temp=21.0,humid=54;` |
| 文本：JSON 负载 | `{"device":"sim-01","uptime":0,"temp":21.0}` |
| 二进制：A5 帧 | `A5 <t> <h> <sum> 5A` |

选择二进制脚本时还会顺带把结构表填上它所需的 schema，因此不必先手工搭一张表才能看到解码结果。

### 载荷模板与帧模板

两个输入框都会预先填入所选脚本的默认模板，所以格式是看得见、能改的，而不是靠提示猜。只显示与当前脚本相关的那一个——文本脚本显示载荷模板，二进制脚本显示帧模板——「恢复默认」可以随时回到默认值。自己写过的模板在切换脚本时不会被覆盖。

载荷占位符（文本脚本）：

| 占位符 | 展开为 |
| --- | --- |
| `{temp}` | 温度，一位小数 |
| `{hum}` | 湿度，整数 |
| `{n}` | 帧计数 |
| `{tick}` | 与 `{n}` 同值，作为别名保留 |
| `{ts}` | 本次会话累计帧数 |

帧占位符（二进制脚本）：`{t}` 温度×10、`{h}` 湿度、`{n}` 计数、`{sum}` 仅对占位符产生的字节求 SUM8 —— 与校验和行的计算范围一致，因此帧解码时校验和是合法的。字面十六进制段（`A5` 帧头、`5A` 帧尾）属于帧结构，不参与求和。

「下一帧预览」显示下一个 tick 将要发出的确切文本或字节（按当前模板展开）。没有它，一个打错的占位符和一个卡住的模拟器是无法区分的。
