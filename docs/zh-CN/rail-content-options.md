# 左栏空白 —— 它到底是什么，以及能放什么

分支：`feat/modernist-ui`。与 `docs/layout-redesign.md`、
`docs/rail-ui-changes.md` 同批。

---

## 空白是一个预留的网格行，不是没用上的空间

`.left-column`（`style.css:1996`）是：

```css
grid-template-rows: auto minmax(0, 1fr);
```

两行网格，但它**只有��个**子元素——`.expanded-left-top`，里面包着
`.config-panel`。第二行 `1fr` 本来是给 `.parser-panel` 的，
而 `style.css:2712` 把它隐藏了：

```css
body:not(.layout-expanded):not(.compact-single) .parser-panel,
body:not(.layout-expanded):not(.compact-single) .charts-panel {
  display: none !important;
}
```

实测：左栏 934px，`config-panel` 432px。那 502px 的差额就是
**没有任何内容的 `1fr` 行**。

**所以诚实的说法是：解析面板本来就属于那里，只是被有意隐藏了，
而不是左栏有多余空间放新东西。** 这个区别决定了整个问题的答案，
所以值得说准。

### 解析面板为什么默认隐藏

`layout-toggle-btn`（`index.html:279`）的文案是 图形解析模式
（`app.core.js:2450`）。图形解析是一个可选工作流：二进制分帧加图表。
**文本解析——规则框、实时结果卡——在默认视图就能用**，
`C3` 的模拟器也是喂给它。只有图形解析的*配置*（二进制结构表、图表列表）
藏在开关后面。

这是个站得住的产品决策，但它带来了下面两个真问题。

---

## 当前安排的两个真问题

### 1. 模式开关藏在它自己要切换的面板里

`layout-toggle-btn` 在 `index.html:279`，位于 `.config-panel` 内部
（145–286 行）。也就是说，**进入图形解析模式必须先展开连接面板**——
那个用来离开连接视图的控件，被埋在了连接视图里面。

而且切过去之后，实测 `chartsPanel 1574x80`、`monitorPanel 0x0`：
左栏装着配置 + 解析 + 图表，而监视器被整列换掉。
一个叫「图形解析模式」的开关读起来像视图切换器，实际却换掉了整个右列。

### 2. `layout-expanded` 是替换，不是叠加

实测数据在上一轮：展开态图表占 1574x80，监视器 0x0。
**串口会话的实时视图整个消失了。** 对一个叫「图形解析模式」的控件来说，
这是意外的——用户并没有要求停止监视。

这就是为什么即使不算那个空行，左栏也让人觉得不对：
布局有两种形状而不是连续空间，而且更高的那一种会把监视器藏掉。

## 三个选项，诚实排序

### 选项 1 —— 单行左栏，空间还给监视器

```css
.left-column { grid-template-rows: auto; }
```

左栏缩到约 440px，监视器多拿约 490px。

**代价。** 图形解析在默认视图里失去入口，因为用来显示解析配置的开关
本身就在连接面板里，而那个面板会被改成整列高度。
这是真的先有鸡还是先有蛋：要���解析设置才能用图形解析，
而通往那些设置的按钮埋在被缩短的那个面板里。

实现最省，而且它是让空行**消失**而不是填满。

### 选项 2 —— 解析面板默认可见，左栏成为两个真面板

去掉 `.parser-panel` 的 `display: none`，只把图表列表留在开关后面。
`1fr` 行拿到了它本来的住户，左栏读作「连接 + 解析」——
正是这块空间被预留时的含义。

**代价。** 解析配置面板很高（规则编辑器加二进制结构表）。
432px 连接面板加一个解析面板，列在较矮视口下会滚动——
需要在实测的 1000px 高度下验证。

**这是我推荐的选项**，因为它让布局变得**有意义**，而不只是变小。

### 选项 3 —— 把模式开关移出连接面板

放进 topbar 或角落操作区，这样无论左栏显示哪个面板都能点到，
同时把 `layout-expanded` 改成叠加式：监视器保持可见，只移动图表。

**与 1、2 相互独立。** 它修掉的是「控件被埋」和「我的会话消失了」
两个问题。无论如何都值得做。

## 真正能填进去的东西

如果问题的答案确实是「加点什么」，下面是候选——**全部已经实现**，
且全部在默认视图下没有可达入口。每一个都是**新增表面**而不是填空，
所以每一个都应该单独决策，不该打包进一次布局修改。

| 候选 | 代码现状 | 为什么值得占这块空间 |
| --- | --- | --- |
| **发送模块入口** | 定时发送 / 触发发送 / 预设发送已完整实现（`module-card`，`index.html:532/552/566`），开关在 `index.html:592–600` 的监视器发送区，默认全折叠 | 自动化是用这个工具的主要理由，而找到它要滚过整个监视器。左栏各占一行，还能让每个模块的设置保持可见 |
| **图表条** | 时域图 / 频域图 / 柱状图在 `index.html:357` 的 `charts-panel`，而它是 `.workspace` 的**兄弟节点而非子节点** | 图表是全 app 唯一的可视化入口，而它在默认视图下**完全没有入口** |
| **会话统计** | `stats-grid` 在 CSS 里（`style.css:2386`）存在但 `index.html` 里**没有元素** —— 孤儿 CSS。`state.session` 已记录 `rxBytes`、事件数、时长 | 状态药丸只显示连接时长，不显示流量。一个实时字节/事件计数能回答「这条链路真的在传数据吗」 |
| **设备档案** | VID/PID 是两个悬空的 `-`（`index.html:151`），无任何存储 | 串口设备数量有限且会被反复使用。按 VID/PID 记住波特率与流控是真实使用路径，也能把 VID/PID 从装饰变成键 |

我的排序：**设备档案**第一（真实价值最高、表面最小——数据本来就在显示），
然后**会话统计**（孤儿 CSS 已经在那儿了），
然后**发送模块入口**（收益最大、表面也最大），
最后**图表条**（让 `layout-expanded` 变叠加式就已经处理了）。

注意这是本项目**第八次**遇到孤儿 CSS / 无入口的情况。
模式是一致的：`stats-grid` 是为一个从未建出来的面板写的，
和 `.insight-pre` 为一个从未创建的元素写样式完全一样。

## 建议

按顺序做**选项 3 + 选项 1/2 之一**，设备档案作为独立的功能提交。

- **先做选项 3。** 它是行为修正（叠加而非替换、开关可达），
  不依赖行数决策。
- **再做选项 2。** 让解析面板成为默认住户，是把空行变成意义的那一步。
  如果解析面板在 1000px 高度下放不下，再退回选项 1。
- **设备档案**之后，作为独立提交——它是带存储的新功能，不是布局改动。
